# NERO Firefox ローカル自動運転

NEROの自動スキと「ネロのお気に入り🌙」への追加は、外部実行サーバーやユーザー定義GitHub Actionsを使わずFirefox拡張内で実行します。

## GitHub Pages

Reader UI は `https://cosmos-invest.github.io/nero-swipe-reader/` を正規URLとします。GitHub Pagesは画面だけを配信し、自動処理やnote認証は保持しません。

## 通常運転

- Firefox `browser.alarms` で5分おきに起動
- 1回につき候補1記事
- 直近60分で通常のマガジン追加は最大10件
- 候補は `はじめてのnote / note初心者 / 初投稿 / 自己紹介 / 挑戦 / 日常 / noteを楽しむ / 創作` から巡回
- 同一クリエイター7日、同一記事30日の重複処理を抑止
- noteログイン中のアカウントを初回ON時に端末へ固定し、以後完全一致を要求
- スキ制限時はスキだけ1時間休止し、マガジン追加は継続

## 過去スキ整理 v0.1.33

Pagesの「過去スキを確認」から、ログイン中の本人が過去にスキした記事を全ページ確認できます。確認後に「同期を開始」を押すと、`ネロのお気に入り🌙` へ12秒以上の間隔で順番に追加します。

- 既にマガジン入りの記事は `追加済み` として処理
- 同期中は通常自動運転を一時停止
- 完了後は同期開始前の自動運転ON/OFFへ復帰
- 5件ごとに進捗を保存して次のalarmへ引き継ぐ
- Firefox再起動時も `running` 状態なら続きから再開
- 失敗した記事は勝手に飛ばさず、その位置で一時停止
- 過去スキ整理の件数は通常運転の「直近60分10件」には含めない

過去スキ一覧はnote Web UIで使われている非公式の `/api/v2/creators/{urlname}/likes?page=N` 系を利用するため、note側の仕様変更時は安全側に停止します。

## 履歴

自動運転と過去スキ整理の結果をFirefox `browser.storage.local` に保存し、Pagesの「処理履歴」に表示します。

- 最大2,000件
- 最長365日
- 記事キー、タイトル、クリエイター、日時、追加結果、スキ結果
- v0.1.32までに保存済みの `events` も同じストレージキーから引き継ぐ
- 外部サーバーへ送信しない

## 全体停止する条件

- note未ログイン
- 固定したNEROアカウントと現在のログインアカウントが違う
- `ネロのお気に入り🌙` が見つからない / 同名が複数ある / 無料マガジンではない
- マガジン追加結果が不明
- noteとのマガジン通信に失敗

## GitHub / Cloudflare

- ユーザー定義 `.github/workflows`: なし
- GitHub Pages内部deployment workflow: Pages公開時のみGitHub側で実行。Publicリポジトリの標準runnerなので課金対象Actions分数は0
- Cloudflare: 使用しない
- GitHub Pages: `docs/` を `main` ブランチから静的配信
